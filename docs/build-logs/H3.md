## Implementation notes (built 2026-09-19)

1. **`await params` from the start** — the single dynamic route (`suites/[slug]/page.tsx`) types
   `params: Promise<{ slug: string }>` and `await params` in both `generateMetadata` and the page
   component (decision #18). This avoids the H2 dev-only bug where synchronous `params.slug` read
   404'd every dynamic route under Playwright while the SSG build still passed.
2. **Identity kept distinct** — ivory/maroon/gold palette, Marcellus + Karla, the "gild" light-sweep
   motion, and the diamond ornament + numbered lineage motif. Deliberately avoids H1's hairline rules
   and H2's dotted-leader/specimen motif (brief §Do-not-use).
3. **Shared primitives only** — `Container`, `Img`, `Reveal`, the form kit (RHF + zod), and the
   SEO/JSON-LD helpers from `@site-lab/shared`; no visual language leaks in from the shared package.
4. **Ledger as a single court-record page** — the brief listed "The Ledger (list) · Ledger detail ×4";
   the build consolidates this into one `/ledger` page with six numbered entries (a family ledger read
   top-to-bottom). This is a deliberate simplification, not a data mismatch — the entries are the record.
5. **Demo-only reservation** — the reserve form validates client-side (RHF + zod) and reaches a success
   state; nothing is sent or stored (Bible §10). No fake reviews, awards, badges, gradients, or glassmorphism.

  motion/motif. They do not make the two sites read as "same template, different colors."
- **H2 and H3 both target `/reserve`** as the primary CTA. This is a conventional path, not a lifted
  asset or layout.

**Verdict:** H3 is clearly distinct from H1 and H2 on palette, type, motion, motif, city, room concept,
and voice. No re-art-direction required.
